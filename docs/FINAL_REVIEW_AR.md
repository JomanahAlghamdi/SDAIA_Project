## ما صحّحته المراجعة

- أضفت حقول مهام الدورة القياسية وربطتها بمصححات تعمل فعليًا؛ بقيت الاختبارات التفصيلية للمجال والموافقة.
- أصلحت إيقاف التنفيذ قبل أي أداة عند ظهور تكلفة موجبة غير متوقعة، حتى لو كانت دون سقف 0.05 دولار.
- ربطت أدلة الأمان ببصمات الكود، ومنعت قبول نتائج قديمة أو تجارب توقفت بسبب مزود النموذج.
- أضفت إثبات قراءة الوصف الخبيث ووصول محاولة الحفظ إلى بوابة الرفض قبل اعتبار الدفاع مثبتًا في تجربة حية.
- صححت وصف الذاكرة: 12 رسالة تعني ستة أزواج سؤال/إجابة.
- أضفت اختبارات لهذه الحالات؛ راجعي النتيجة الفعلية في [pytest.txt](../results/local/pytest.txt) و[GitHub Actions](https://github.com/JomanahAlghamdi/SDAIA_Project/actions).

## ما يبقى قبل التسليم

1. توفير `OPENROUTER_API_KEY` في **GitHub → Settings → Secrets and variables → Actions**. لا يوضع المفتاح في ملفات الكود أو المحادثة.
2. إكمال تقييم جميع المهام على A وB بالنموذج نفسه. التوقف بسبب غياب المفتاح أو الحصة لا ينتج تقييمًا مكتملًا.
3. إكمال التجربة الأمنية على النموذج وتفسير ما حدث بصدق، حتى لو لم يتبع النموذج الهجوم.
4. مراجعة المحادثات، وكتابة تحليل الأسباب في `docs/error_analysis.md`، وتحديث جدول README بالأرقام الفعلية وتوثيق اختيار النموذج.
5. حفظ ملفات النتائج داخل المستودع وتشغيل `uv run python scripts/readiness.py --require-live` ومراجعة متطلبات الدفعة.

يمكن تشغيل التجارب من GitHub دون تثبيت المشروع محليًا. ملفات النتائج توجد في **Artifacts → live-evaluation-evidence** بعد محاولة التشغيل. لا يكفي وجود هذا الملف أو نجاح خطوة الرفع؛ يجب فحص حالة manifest وعدد الصفوف والتأكد من اكتمال A وB. لا توجد نسبة نجاح أكاديمية مضمونة من مراجعة برمجية وحدها.
